# MILESTONES — איקס עיגול

מסמך זה מגדיר את אבני הדרך המרכזיות לפיתוח אפליקציית **„איקס עיגול”**, בהתאם ל־PRD, ל־ARCHITECTURE ול־DESIGN.

המבנה מבוסס ככל האפשר על **Vertical Slices** — כל Milestone מוסיף יכולת משתמש שלמה, ניתנת להרצה, לבדיקה ולאישור.

> **כלל עבודה מחייב:** לאחר השלמת כל Milestone, על ה־AI לעצור את הפיתוח ולהמתין לבדיקה ולאישור מפורש שלי (המפתח) לפני המעבר ל־Milestone הבא.

---

# Milestone 1 — מעטפת האפליקציה, המסכים והניווט

## מטרה
לבנות גרסה ראשונה עובדת של האפליקציה שבה המשתמש יכול לפתוח את האתר, לראות את שלושת המסכים המרכזיים ולנווט ביניהם בממשק התואם לעיצוב שהוגדר.

## מה יש לממש
- הקמת אפליקציית React + TypeScript באמצעות Vite.
- הגדרת React Router.
- יצירת שלושת המסכים:
  - בית.
  - משחק.
  - אודות.
- יצירת תפריט ניווט עקבי הזמין בכל המסכים.
- מימוש RTL מלא ועברית בלבד.
- התאמה רספונסיבית ל־Mobile ול־Desktop.
- יישום השפה החזותית מתוך `DESIGN.md`:
  - רקע חלל כהה.
  - צבעי ניאון.
  - טיפוגרפיה.
  - כפתורים.
  - מסגרות, פינות, Glow ומרווחים.
- מסך הבית:
  - שם המשחק.
  - תיאור.
  - כפתור „התחל לשחק”.
  - כפתור „אודות”.
- מסך המשחק:
  - תצוגת לוח 3×3.
  - כפתור „משחק חדש”.
  - כפתור Mute/Unmute.
  - בשלב זה אין צורך בלוגיקת משחק מלאה.
- מסך האודות:
  - תיאור המשחק.
  - הטקסט: „פותח על ידי תלמידי ג'ון ברייס התותחים”.

## התוצר המצופה
אפליקציה ניתנת להרצה שבה המשתמש יכול לעבור בין כל המסכים ולראות את המבנה והעיצוב הסופי של המוצר, גם במובייל וגם ב־Desktop.

## Definition of Done
ה־Milestone ייחשב מושלם כאשר:
- האפליקציה עולה ללא שגיאות.
- שלושת ה־Routes עובדים:
  - `/`
  - `/game`
  - `/about`
- ניתן לנווט בין כל המסכים.
- כפתורי „התחל לשחק” ו־„אודות” מובילים למסכים הנכונים.
- כל הממשק מוצג בעברית וב־RTL.
- הפריסה תואמת ל־Wireframes.
- המראה תואם ל־Mockups ול־Style Guide.
- הממשק נראה תקין ב־Chrome במובייל וב־Desktop.
- אין גלישה, שבירה או חפיפה מהותית של רכיבי UI.

# Milestone 2 — משחק מלא מול המחשב

## מטרה
לאפשר למשתמש לשחק משחק איקס־עיגול שלם מול המחשב, מתחילת המשחק ועד ניצחון, הפסד או תיקו.

## מה יש לממש
- מודל מצב למשחק 3×3.
- המשתמש תמיד משחק כ־X.
- המחשב תמיד משחק כ־O.
- המשתמש תמיד מתחיל.
- לחיצה על תא פנוי מציבה X.
- מניעת לחיצה על תא תפוס.
- זיהוי:
  - ניצחון משתמש.
  - ניצחון מחשב.
  - תיקו.
- חסימת הלוח לאחר מהלך המשתמש.
- השהיה של כ־500ms לפני מהלך המחשב.
- מימוש שחקן מחשב חכם אך לא בלתי מנוצח:
  - ניסיון לנצח כאשר אפשר.
  - חסימת מהלך ניצחון של המשתמש.
  - העדפת מרכז.
  - העדפת פינות.
  - בחירת מהלך חוקי אחר.
  - מעט אקראיות במצבים שאינם קריטיים.
- פתיחת הלוח מחדש לאחר מהלך המחשב, כל עוד המשחק ממשיך.
- הצגת הודעת תוצאה בסיום משחק.
- נעילת הלוח לאחר סיום המשחק.
- כפתור „משחק חדש”:
  - מאפס את הלוח.
  - מתחיל משחק חדש.
  - המשתמש מתחיל שוב.
- מעבר ממסך המשחק למסך אחר מאפס את המשחק.
- ביטול Timer פעיל במקרה של:
  - משחק חדש.
  - יציאה ממסך המשחק.
  - Unmount של המסך.

## התוצר המצופה
משחק איקס־עיגול מלא ועובד שבו המשתמש יכול לשחק רצף משחקים מול המחשב ללא צורך ברענון הדף.

## Definition of Done
ה־Milestone ייחשב מושלם כאשר:
- המשתמש יכול לבצע מהלכים חוקיים בלבד.
- לא ניתן לבצע שתי לחיצות לפני מהלך המחשב.
- המחשב מבצע מהלך לאחר השהיה של כחצי שנייה.
- המחשב לעולם אינו בוחר תא תפוס.
- המחשב אינו מבצע מהלך לאחר סיום המשחק.
- ניצחון X מזוהה נכון בכל שמונת צירופי הניצחון.
- ניצחון O מזוהה נכון בכל שמונת צירופי הניצחון.
- תיקו מזוהה כאשר הלוח מלא ואין מנצח.
- בסיום מוצגת תוצאה מתאימה.
- הלוח נשאר במצבו הסופי לאחר סיום המשחק.
- לחיצה על „משחק חדש” מאפסת את המשחק באופן מלא.
- יציאה ממסך המשחק וחזרה אליו מתחילה משחק חדש.
- אין Timer ישן שמבצע מהלך לאחר Reset או מעבר מסך.
- קיימות בדיקות Unit ללוגיקת המשחק וללוגיקת בחירת מהלך המחשב.

# Milestone 3 — חוויית משחק מלאה: שמע, אנימציות ופידבק חזותי

## מטרה
להשלים את חוויית המשחק בהתאם ל־PRD ול־Style Guide, כך שהפעולות והתוצאות יקבלו משוב קולי וחזותי ברור ועקבי.

## מה יש לממש
- Audio Engine המבוסס על Web Audio API.
- אפקטים קוליים מסונתזים עבור:
  - הנחת X.
  - הנחת O.
  - ניצחון המשתמש.
  - הפסד המשתמש.
  - תיקו.
- כפתור Mute/Unmute פעיל.
- מצב Mute נשמר בזיכרון בלבד.
- אין שימוש ב־localStorage.
- טיפול בדרישת User Gesture של הדפדפן לצורך AudioContext.
- אנימציית הופעה קצרה ל־X.
- אנימציית הופעה קצרה ל־O.
- הדגשה חזותית של שלושת התאים המנצחים.
- שמירת הלוח במצב הסופי עד לחיצה על „משחק חדש”.
- התאמת כל האפקטים לעיצוב הניאון שהוגדר ב־DESIGN.

## התוצר המצופה
גרסת משחק מלאה מבחינת UX, שבה לכל פעולה מרכזית יש משוב מתאים, והמשתמש יכול לשלוט בשמע.

## Definition of Done
ה־Milestone ייחשב מושלם כאשר:
- X ו־O מופיעים באנימציה קצרה.
- בסיום ניצחון מודגשים בדיוק שלושת התאים המנצחים.
- לכל אחד מחמשת אירועי המשחק מוגדר אפקט קולי מתאים.
- Mute מפסיק את כל האפקטים הקוליים.
- Unmute מחזיר את האפקטים הקוליים.
- Refresh מאפס את מצב ה־Mute לברירת המחדל.
- כשל באתחול Audio אינו מונע משחק.
- האנימציות אינן מפריעות ללחיצות או ללוגיקת המשחק.
- העיצוב נשאר עקבי במובייל וב־Desktop.

# Milestone 4 — PWA, Offline וגרסת Production

## מטרה
להפוך את האפליקציה ל־PWA תקינה הניתנת להתקנה ב־Chrome ולעבודה מלאה גם ללא חיבור לאינטרנט.

## מה יש לממש
- הגדרת `vite-plugin-pwa`.
- יצירת Web App Manifest.
- הגדרת:
  - שם האפליקציה.
  - Short Name.
  - `lang="he"`.
  - `dir="rtl"`.
  - `display="standalone"`.
  - Theme Color.
  - Background Color.
  - Icons.
- יצירת Service Worker.
- Precache של קבצי ה־Frontend הדרושים להפעלת האפליקציה.
- תמיכה בפתיחת האפליקציה ובמשחק מלא Offline.
- הגדרת SPA fallback עבור Routes.
- Build Production באמצעות Vite.
- פריסה ל־Cloudflare Static Hosting / Workers Static Assets.
- HTTPS פעיל.
- בדיקה של האפליקציה כאתר רגיל וכ־PWA מותקנת.

## התוצר המצופה
גרסת Production מלאה של האפליקציה, נגישה דרך URL, ניתנת להתקנה ב־Chrome ופועלת גם ללא אינטרנט לאחר שהמשאבים הנדרשים נטענו ונשמרו ב־cache.

## Definition of Done
ה־Milestone ייחשב מושלם כאשר:
- `npm run build` מסתיים בהצלחה.
- האפליקציה נפרסת ומונגשת דרך HTTPS.
- שלושת ה־Routes עובדים גם בגישה ישירה.
- Chrome מזהה את האפליקציה כ־PWA ניתנת להתקנה.
- ניתן להתקין את האפליקציה.
- לאחר התקנה וטעינה ראשונית, ניתן לפתוח אותה ללא אינטרנט.
- ניתן לשחק משחק מלא Offline.
- כל המסכים והניווט עובדים Offline.
- האפקטים הקוליים והאנימציות עובדים Offline.
- אין בקשות Runtime הכרחיות ל־Backend או ל־API חיצוני.
- האפליקציה נבדקה ב־Chrome Desktop וב־Chrome Android.
- כל דרישות ה־MVP מה־PRD מתקיימות בגרסת Production.
